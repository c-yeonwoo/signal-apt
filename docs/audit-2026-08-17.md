## ⚠️ 작업 전 반드시 알아야 할 것 — 워크트리에서 검증하는 법

`.venv` 는 **메인 레포에 editable 설치**돼 있다. 그래서 워크트리에서 그냥 `python`·`signal` 을 돌리면
**메인 레포의 `src/` 를 임포트한다.** 워크트리 편집분이 로드되지 않는데도 "통과"가 뜬다.
(이 진단 작업 중 실제로 한 번 잘못 검증했다.)

| 상황 | 올바른 방법 |
|---|---|
| `pytest` | 그냥 돌려도 된다 — `pyproject.toml` 의 `[tool.pytest.ini_options] pythonpath=["src"]` 가 처리 |
| `python -c ...` · 스크립트 | **`PYTHONPATH=src` 를 반드시 붙인다** |
| dev 서버 | `.claude/launch.json` 이 `python -c "sys.path.insert(0,'src')"` 로 뜨게 돼 있다. 바꾸지 말 것 |
| dev 서버 (브라우저 프리뷰) | **프리뷰 도구는 세션이 처음 열린 디렉토리의 `.claude/launch.json` 을 읽는다.** 워크트리를 옮겨도(EnterWorktree) 바뀌지 않는다 — 2026-09-06 에 이걸로 **koczip 제거 전 코드가 뜨면서 403 크롤링이 다시 돌았다.** 다른 워크트리 코드를 띄우려면 **원래 디렉토리의** launch.json 을 절대경로로 고쳐야 한다 |
| 확인법(서버) | `curl -s localhost:8765/ \| grep -c '<새로 추가한 JS 함수명>'` → 0 이면 옛 코드다. 라우트 404/401 은 미들웨어가 전부 401 로 덮어서 판별에 못 쓴다 |
| 확인법 | `PYTHONPATH=src .venv/bin/python -c "import realty_signal.api as a; print(a.__file__)"` → 경로에 `worktrees` 가 있어야 한다 |

`data/cache` 와 `.env` 는 메인 레포에서 **복사**해 왔다(진단용 사본이라 실제 데이터를 안 건드린다).
`.venv` 심볼릭 링크는 `.git/info/exclude` 에 넣어 커밋에서 뺐다.

### ⚠️ 완료 조건을 스스로 정정한다

원래 적었던 완료 조건은 *"예산 6억 사용자의 추천에서 서울 **초과가** 매물이 상위를 점유하지 않고,
비서울 예산 내 매물이 나온다"* 였다. 앞쪽 절반은 **전제가 틀렸다.**

실측해 보니 노원·도봉·구로 같은 **싼 서울 구가 6억에 실제로 들어온다.** 즉 상위를 점유하던 건
"예산 초과 서울 매물"이 아니라 "예산 내 서울 STRONG_BUY 매물"이었다. 예산 필터의 문제가 아니라
**등급 사다리(`_SIG_RANK*10000` 지배)의 문제**다 — 그건 N8 이고 V-1·V-2 선행이라 지금 건드리지 않는다.

그래서 N2 의 실제 성과는 두 가지로 정리한다:
1. 등급에 의한 **하드 폐기 제거** — BUY 797건이 후보에 복귀했다
2. **지역 독식 방지** — 한 동네 11건 → 최대 3건, 그 결과 6억 예산에 비서울 7건이 실제로 올라왔다

15억 예산에서는 여전히 상위 40건이 전부 서울 STRONG_BUY 다. 이건 결함이 아니라
**등급 사다리가 아직 데이터로 검증되지 않았다는 사실의 표현**이다(N8 대기).

**성공 측정**: 추천 결과의 비서울 비중 · 예산 내 비중 (측정 수단 없음 → N4).

## V-1 결과 — 세 재료가 각각 무엇을 더하는가 (2026-08-17)

**앵커 불일치부터 해소했다.** 진단이 나란히 놓았던 두 수치는 애초에 비교 불가였다 —
모멘텀 94.5% 는 *조건을 만족하는 매 주차*, 성적표 86.3% 는 *구간 종료 시점* 기준이었다.
같은 앵커(조건 만족 모든 지역×주) · 같은 기준선(같은 날짜 전체 지역)으로 다시 쟀다.

|---|---:|---:|---:|---:|---:|

상승률이 오르는 건 예측력이 아니라 **더 뜨거운 시장만 골라내기 때문**이다 —

### 재료별 순수 기여 (나머지 둘 고정, 하나만 토글)

### ⚠️ 전세난은 "해롭다"가 아니라 "증거가 없다"

풀링하면 **−0.17%p** 인데 **연도 평균은 +0.15%p** 로 **부호가 뒤집힌다.**
표본이 많은 2014~16년이 풀링 결과를 끌고 간 것이다(Simpson 류 역전).
연도별로도 2011 +0.80 · 2020 +0.25 · 2021 +0.33 은 양수, 2014~16 은 작은 음수다.

→ 올바른 판정은 **"일관된 기여 증거가 없다"** 지 "빼야 한다" 가 아니다.
   전체 평균 하나로 재료를 버리면 진단이 지적한 바로 그 실수(base rate·표본 구조 무시)를 반복한다.

### N8 에 넘기는 것

1. **3조건 동일 가중은 지지되지 않는다.** 두 재료(모멘텀·매수우위)는 일관되게 기여하고

## 결정 필요 — 내가 대신 정하지 않는다

### D1. 간판 문장 — ✅ **결정됨 2026-08-17: 현행 유지, V-2 까지 보류**

간판은 **"근거가 증명되는 매수 타이밍"** 그대로 둔다.
**이유**: 문장을 뒤집으라는 근거가 전부 KB 주간 **지수** 기반이다. 국토부 실거래가로 재검증(V-2)하기 전에
간판을 바꾸면, 근거 없이 근거를 바꾸는 셈이 된다 — 이 제품이 고치려는 바로 그 실수다.

따라서 **N7(문장 교체 + 홈 판정 카드)은 V-2 완료 전까지 착수하지 않는다.**
V-2 가 이제 단순한 검증 과제가 아니라 **간판을 푸는 열쇠**다 — 검증 과제 중 우선순위 최상위로 올린다.

보류 중 감수하는 것: 그 사이 사용자가 이 시그널로 매수 *시점*을 고를 수 있다.
완화책으로 N1 에서 이미 성적표에 시장 대비 초과분과 주의 3문장을 노출했다 —
"86%"만 보고 판단하지 않게 하는 최소한의 장치는 걸려 있다.

검토했던 대안(V-2 이후 다시 꺼낼 것):

| 안 | 문장 | 근거 강도 | 트레이드오프 |
|---|---|---|---|
| A | "살 때가 아닌 곳을 먼저 걸러 드립니다" | 가장 강함 (SELL 초과 −1.14%p) | "사라"고 안 하면 재방문 동기가 약해질 수 있다 |
| B | "타이밍은 걸러내고, 예산으로 좁힙니다" | 중간 | 진술한 우선순위(V1 먼저)를 뒤집는다 |
| C | "매수 시점보다 매수 지역" | 중간 | 초과수익 +0.25%p 는 여전히 비용 안 |
