## 1 시작 전 확인

1. `git status --short`, 현재 HEAD, 해당 시점 AGENTS.md와 최신 사용자 요청을 확인한다. 설계 작성 당시 기존 미추적 파일은 `docs/HANDOFF-2026-10-03.md`였으며 사용자 파일이다.
2. 최신 main과 차이를 읽고 아래 파일 경로·계약이 아직 맞는지 확인한다. 문서에 적힌 줄 번호나 오래된 테스트 개수에 의존하지 않는다.
3. 현재의 커밋·머지 권한은 실제 구현 요청에서 확인한다. 이전 대화의 자동 머지 요청만으로 이 설계 턴에 배포하지 않는다.
4. 로컬 격리 DB와 합성 데이터로 테스트한다. 단순 pytest·브라우저 시험이 운영 수집·메일·유료 모델 호출을 실행하지 않게 한다.
5. 운영 DB 변경은 백업·복구 계획과 적용 대상을 확인한 뒤 별도 배포 단계로 수행한다. 원천 backfill은 범위와 quota를 확인하고 단순 조회 요청에서 시작하지 않는다.

## 3 리팩토링 경계

FastAPI·Python·SQLite·Leaflet·ECharts를 유지한다. 새 프런트엔드 부분은 네이티브 ES module로 분리하고 기존 전역 함수는 어댑터로 호출한다. 단일 HTML 전체를 한 번에 프레임워크로 교체하지 않는다. 신규 static 파일 제공 경로와 설치 패키지 데이터 포함 여부를 테스트한다.

`api.py` 내부 `_build_listings`를 직접 import하는 기존 순환 의존은 새 서비스에서 늘리지 않는다. 원천 조회 인터페이스를 주입하고 route가 사용자 권한과 종속성을 구성하도록 이동한다. `buyer_decision`과 금융 계산기를 별도 구현해 서로 다른 금액이 나오는 경로를 만들지 않는다.

신규 추천은 일반매물·급매·찐매물의 공통 호가 계약부터 적용한다. 경매·청약·재건축은 같은 카드 컴포넌트를 쓰더라도 price_kind·권리·자격·추가 비용 상태를 유지한다. 경매 최저가를 예산 충족 호가로 넣지 않는다. 기존 후보·찜·관심지역·프로필·대화 데이터를 삭제하는 정리는 이 범위 밖이다.

## 4 출시와 되돌리기

제안 flag는 서버가 내려주는 `report_v2_enabled`, `discovery_v2_enabled`, `contextual_explanations_enabled`, `nick_global_entry_enabled`다. 권한 플래그가 아니며 개인용 원천 접근은 별도 인증으로 검사한다.

1. 새 판정 저장과 추천을 비공개 shadow 실행한다. 운영 결과와 비교하되 알림·화면을 바꾸지 않는다. 추가 원천 조회나 LLM 자동 호출을 유발하지 않는다.
2. 데이터 정합·권한·설명 테스트 통과 후 지정 사용자에게 독립 리포트를 켠다. 기존 흐름은 유지한다.
3. 발견 UI와 목적별 홈을 켜고 실제 과업을 검증한다. 결과 분포 변화는 의도된 정책 차이와 버그를 구분한다.
4. 기존 Nick 질문 중 가격 근거·장단점·비교·내 조건 설명이 새 흐름에서 가능한지 확인한 뒤 FAB를 숨긴다.
5. 장애 시 UI flag를 되돌리되 보안·지역 식별·오판 방지 수정까지 되돌리지 않는다. 새 DB 테이블과 issued 기록은 보존한다. legacy UI도 안전 상태를 존중하는 어댑터를 사용해야 한다.

데이터 migration은 새 테이블 생성, 검증 가능한 매핑만 backfill, dual-read 비교, read 전환 순서로 수행한다. 쓰기 두 군데를 독립 성공으로 가정하지 않고 하나의 트랜잭션과 outbox를 쓴다. profile·즐겨찾기 변환은 idempotent하며 기존 값을 덮어쓰기 전에 원본 참조를 남긴다. 운영 변경 전 실제 백업 복구 절차를 확인한다.

## 5 필수 테스트 명세

다음은 신규 테스트 제안이며 아직 작성하거나 실행하지 않았다. 기존 테스트는 삭제하지 않고 의도적으로 달라지는 제품 계약만 새 버전 기준으로 갱신한다.

### 5.1 판정과 변화 설명

- `test_signal_assessment.py`: 전세 180·심리 80에서 가격 결측은 보류, 평균 가격 음수와 raw BUY 충돌도 보류. raw 값은 보존한다.
- 최근 4개 행이 있어도 달력상 중간 주가 없으면 불충분이다. 잘못된 지역 매핑·NaN·Infinity·만료 자료도 검사한다.
- 주간 평균과 4주 누적은 값·단위·문구 모두 구분한다. 임계값 정확히 일치한 경계와 바로 아래·위를 검사한다.
- 심리 70 이상이 공식 균형선 100 초과로 설명되지 않는다. 전세 압력이 실제 매매 전환을 증명했다는 문구를 생성하지 않는다.
- `test_signal_issuance.py`: 같은 입력 재시도 중복 없음, 규칙 변경 시 새 기록, 과거 issued 불변, reconstructed 분리, 원천 수정 구분.
- 최초 기록에는 지난주 대비 상승·하락을 만들지 않는다. 같은 등급의 근거 변화와 규칙 변경만으로 달라진 등급을 구별한다.
- 기존 `test_engine.py`, `test_engine_golden.py`, `test_evaluation_protocol.py`, `test_scorecard_honesty.py`를 함께 실행한다.

### 5.2 추천과 조건

- `test_discovery_v2.py`: 모든 시그널 등급의 조건 부합 후보가 검색 가능하다. 강력매수라도 필수 조건 fail이면 기본 부합 그룹에 없다.
- 필수 통근·가격·입주일 unknown은 pass가 아니다. 금융 계산 미확인은 가격만 맞는다고 구매 가능으로 승격되지 않는다.
- unknown 선호의 분모를 줄여 점수가 올라가지 않는다. 알려진 항목이 더 충족되면 정렬 점수가 떨어지지 않는다.
- 선호 없는 요청, 후보 0개, 한 지역 한 단지만 선택, 다양성 제한 이후 overflow, stale와 중복 원천을 검사한다.
- 페이지 이동 중 후보 스냅샷 변경, 권한 회수, 동일 정렬값 tie-break, 악성 cursor를 검사한다.
- 경매 최저가와 일반 호가, 공급자 급매 라벨과 검증 가격 비교를 구분한다.
- `test_recommend.py`, `test_buyer_decision_contract.py`, `test_personal_listings.py`, `test_request_isolation.py`, `test_compare_safety.py` 회귀를 유지한다.

### 5.3 리포트와 AI

- `test_reports_v2.py`: 지역·매물·비교 화면의 동일 evidence 값 일치, 비교기간·단위·공간 범위 유지, 중요 위험이 요약에서 사라지지 않음.
- report ID만 아는 타 사용자가 개인 리포트·job·질문 결과를 읽지 못한다. 프로필 변경·권한 회수 후 캐시 hit도 재검사한다.
- 원천 날짜 미확인에 생성시각을 넣지 않는다. building·location 장애에도 기본 가격 섹션은 유지된다.
- 기본 리포트 R1의 입지 보강은 새 R2를 만들고 R1 내용·설명을 덮어쓰지 않는다. 오래된 발행 상태와 현재 serving_freshness를 구분한다.
- `test_report_narrative.py`: 존재하지 않는 evidence ID, 미제공 숫자·가격 전망·권리 확정, 기사 속 지시문, 변경된 evidence hash를 거부한다.
- LLM 실패·비용 제한·cancel·lease 만료 후 복구·중복 요청에도 기본 리포트 정상, 원가 중복 청구·예약 처리 일관성.
- GET과 단순 열람이 유료 모델·원천 refresh를 실행하지 않는 spy 테스트를 둔다.

### 5.4 브라우저와 접근성

- 매물 클릭→상세, 같은 매물 재클릭→닫힘. 찜·비교 버튼은 의도치 않은 상세 토글 없음.
- 지역→매물→비교→뒤로 가기에서 필터·지도·스크롤 복원. 기존 hash 진입도 동작.
- 리포트 열기만으로 advisor 요청 0회. 설명 버튼에서만 요청.
- A→B 전환 중 A의 늦은 결과, 로그아웃·계정 교체, 권한 만료 시 잘못된 정보 노출 없음.
- 360px·390px 모바일 및 데스크톱, 200% 확대에서 주요 과업 가능. 키보드 Enter·Space·Escape·포커스 복귀 검사.
- map vendor 대체 합성 테스트와 실제 타일 확인을 구분해 기록. 운영 인증 전체 E2E를 합성 테스트로 대체했다고 주장하지 않음.

## 6 검증 명령과 결과 기록

환경을 먼저 확인하고 저장소의 현재 lock·CI 명령을 우선한다. 기존 실행 진입점은 아래와 같다.

```sh
.venv/bin/python -m pytest -q
node --test tests/ui_runtime.test.cjs
node tests/ui_browser.cjs
git diff --check
```

브라우저 런타임·Playwright 의존성이 없으면 기존 CI 구성에 맞춰 설치하며 임의 최신 버전을 선택하지 않는다. 구현마다 실행한 명령·성공/실패·스킵 이유·운영 미검증 항목을 기록한다. 합성 테스트 통과를 예측 수익률·실제 사용자 검증·운영 배포 성공으로 쓰지 않는다.

성능 목표 측정은 warm/cold, 데이터 건수, 네트워크·기기, p50/p95, 외부 API 포함 여부를 기록한다. 비용 측정은 모델·prompt 버전과 실제 사용량을 남긴다. 전환 조건은 서버 테스트뿐 아니라 핵심 사용자 과업 성공을 포함한다.

## 7 첫 구현 요청에 사용할 내용

아래 문장을 다음 구현 작업에 전달하면 된다. 모델 선택은 사용자가 별도로 수행한다.

> docs/SIGNAL-APT-2.0-DESIGN.md와 docs/SIGNAL-APT-2.0-IMPLEMENTATION.md를 읽고 최신 코드와 차이를 확인한 뒤 패키지 01부터 순서대로 구현해줘. 먼저 지역 식별·판정 근거·발행 이력을 정비하고, 독립 리포트와 조건 기반 매물 발견을 연결해줘. 기존 데이터·개인용 원천 권한·자금 안전장치를 보존하고, Nick은 리포트 대체 검증 전 삭제하지 마. 예측 임계값을 임의 최적화하거나 서비스 LLM 등급을 바꾸지 말고 각 패키지의 테스트와 미검증 항목을 기록해줘. 커밋·머지·배포는 이 구현 요청에서 내가 정한 범위에 따라 진행해줘.

## 8 설계 완료 확인

- 사용자 여정, 목적별 진입, 메뉴, 리포트 순서와 상호작용 정의 완료.
- 시그널 등급과 안전 상태, 근거·변화 원인·반증 조건의 구분 정의 완료.
- 필수 조건 3상태, 선호 계산, 후보 다양성, 카드 이유·빈 상태 정의 완료.
- 공통 개체, 인증 경계, 신규 API, 비동기 작업, 캐시와 비용 기준 정의 완료.
- Nick 단계 전환, 저장 migration·rollback, 구현 패키지·테스트·출시 조건 정의 완료.
- 미완료는 애플리케이션 구현, 실제 화면 제작·렌더 검증, 운영 원인 진단, 성능·비용 실측, 예측 성능 검증이다. 설계 완료와 제품 완료를 구분한다.
