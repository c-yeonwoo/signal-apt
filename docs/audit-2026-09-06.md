## 2. 구조적으로 "계단식"인 이유 (고장이 아니라 설계 결과)

- **임계값 양자화** — 등급은 3표 합산이라 지수가 0.71 움직여도 표가 안 바뀌면 등급은 그대로.
- **광역 상속** — 117개 지역 중 92개가 전세수급·매수우위를 부모 광역에서 상속.
  서울 11개 구가 동일한 69.29(임계값 70 대비 −0.71)를 공유 → 같이 움직이거나 같이 안 움직인다.
- **전세난 표가 사실상 상수** — 94% 지역에서 충족. 3표 중 1표가 항상 켜져 있으면 해상도가 준다.
  V-1 절제 실험: 모멘텀(5/5년 양), 매수우위지수(11/11) 는 일관 기여, **전세난은 부호가 뒤집힌다**
  (pooled −0.17%p / 연평균 +0.15%p). 사다리 재설계는 V-2 선행 대기.

### 지켜야 할 규칙 (R1~R5 공통)

- **스냅샷 키는 기능마다 따로.** 복귀(`last_visit:`)·예산(`budget_snap:`)·브리핑(`briefing_snap:`)이
  같은 키를 쓰면 한쪽이 보여줄 때 다른 쪽 변화가 사라진다.
- **스냅샷은 보여준 뒤에만 전진한다.** 발송/렌더 실패 시 기준점을 옮기면 변화가 유실된다.
- **광역 상속 지표는 발표 단위로 묶어 보여준다** (`weekly._INHERITED` 규칙 동일 적용).
- **캐시 스키마를 바꾸면 `CACHE_VER` 를 올린다.** R4 에서 옛 kv 캐시가 ★ 를 조용히 무력화했다.
- **0 에는 이유를 붙인다.** "변화 없음"·"비교 대상 없음"·"계산 실패"가 화면에서 같아 보이면 안 된다.

### R5 에서 새로 배운 함정

- **총거래로 비교하면 거짓이 된다.** 실거래는 24개월 롤링 윈도라 새 거래가 생겨도
  오래된 달이 빠지면서 총거래가 *줄 수 있다*. 월별(`ym`) 건수로 비교한다.
- **스냅샷이 기억하지 못하는 달은 비교하지 않는다.** 보관은 최근 3개월뿐이라 그보다
  오래된 달의 차이는 '새 거래' 가 아니라 '모른다' 다.
- **조회 불가와 거래 없음은 다르다.** `'서울'` 처럼 시·도로 등록된 관심단지는 국토부 실거래를
  조회할 수 없다(11000 같은 시도 코드로는 조회가 안 된다). 이걸 '거래 없음' 으로 표시하면
  매주 조용히 거짓말한다 — 사유를 그대로 화면에 낸다.
- **주력 평형이 바뀌면 금액을 비교하지 않는다.** 23평 → 34평은 '1.2억 상승' 이 아니다.
- **브리핑과 홈은 기준점을 따로 쓴다.** `cw.scan()` 이 기준점을 인자로 받는 이유다 —
  브리핑은 자기 스냅샷(`briefing_snap:`) 안에, 홈은 `complex_snap:{uid}` 에 담는다.

## 4. 남은 것 / 확인 필요

- **prod 급매 스캔이 매일 도는지 미확인.** R3 가 변화를 보여주려면 이게 선행이다

- **관심단지 실거래 캐시를 채우는 건 주간 워밍(`warm_favorite_complexes`)과 단지 상세 조회뿐이다.**

  그래서 한 번도 열어보지 않은 관심단지는 "아직 수집하지 않았습니다" 로 나온다.
- `'서울'` 로 등록된 관심단지(상계주공9단지)는 시군구로 다시 등록해야 실거래가 붙는다.
  등록 UI 가 시도만 넘기는 경로가 있는지 확인 필요.
- SMTP·`TELEGRAM_BOT_TOKEN` 은 **운영자가 설정해야** 실제 발송이 켜진다. 지금은 상태만 정직하게 표시.
