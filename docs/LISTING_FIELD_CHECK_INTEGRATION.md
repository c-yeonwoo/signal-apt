# 매물 현장 확인: 사진·거리뷰·후기 연동 기준

리포트의 첫 화면은 현장 확인 행동을 우선한다. 데스크톱에서는 왼쪽 비모달 패널로 열어 오른쪽 매물 지도를 계속 조작할 수 있다. 좁은 화면에서는 지도 위에 하단 패널을 얹고 `지도 크게`로 지도 공간을 확장한다. 리포트는 사진·거리뷰·후기, 비교 가능한 가격, 내 예산, 현장 확인 두 가지에만 답한다. 확인되지 않은 입지·가격·자금 문구를 늘어놓지 않고 근거와 AI 설명은 접어 둔다.

## 현재 연결

| 자료 | 연결 방식 | 사용자에게 표시할 한계 |
|---|---|---|
| 네이버 부동산 | 바로이집 `complex_no`가 검증된 숫자일 때만 네이버 단지 페이지. 한방 매물 등 매칭 ID가 없으면 지역·단지명 검색 | 단지 페이지/검색 결과는 선택한 동·호수의 실제 매물·사진이 아닐 수 있음 |
| 네이버 지도 | 지역·단지명 검색 결과 | 사용자가 거리뷰를 선택하고 실제 출입구·동 위치를 확인해야 함 |
| 호갱노노 | 단지명과 지역으로 후기 검색 | 후기 작성일, 실제 거주 여부, 동일 단지 여부는 확인되지 않음 |
| 아실 | 단지명과 지역으로 단지톡 검색 | 위와 같음 |

외부 후기·사진 원문을 수집·저장하거나 리포트 점수에 반영하지 않는다. 현 수집 매물에는 검증된 실내 사진, 현장 거리뷰 시점, 호갱노노·아실 단지 ID가 없다. 단지 사진을 특정 매물 내부 사진처럼 보여 주면 오인 가능성이 크다. 네이버의 [공개 API 목록](https://developers.naver.com/docs/common/openapiguide/apilist.md)에는 부동산 매물/사진 API가 명시되지 않는다. 후기/사진 재게시가 필요하면 각 제공자와 데이터 사용 범위·표기·보관 기간·갱신/삭제 조건을 먼저 확정한다.

## 다음 통합 조건

1. 매물 사진: 제공자에게 `source_listing_id`, 사진 URL/라이선스, 촬영 대상(실내/단지/주변), 촬영·갱신 시각을 요청한다. `source_listing_id` 일치 전에는 사진을 매물 리포트에 삽입하지 않는다.
2. 거리뷰: 실제 출입구 좌표를 확인한 경우에만 그 위치로 열고, 그렇지 않으면 단지명 검색을 유지한다. 거리뷰 촬영 시점과 단지 좌표·출입구 좌표 차이를 표시한다.
3. 후기: 제공자별 단지 ID 매칭을 주소·좌표·명칭으로 수동 검수한다. 작성일·출처·원문 링크와 함께 장단점 표본으로만 보여 주고, 단일 후기를 사실·투자 점수로 승격하지 않는다.
4. 품질 게이트: 매물/단지 오매칭 0건, 링크 유효성, 모바일에서 지도·외부 사이트 왕복, 사용자 5명 현장 확인 과업을 검증한다.
