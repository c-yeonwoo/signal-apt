# Signal APT 3.0 제품·UX 로드맵

이 문서는 3.0의 구현 순서와 검증 기준이다. [2.0 설계](SIGNAL-APT-2.0-DESIGN.md), [출시 증거](SIGNAL-APT-2.0-RELEASE-EVIDENCE.md), [경매 입찰 시뮬레이터](AUCTION-BID-ENGINE.md)를 대체하지 않는다. 2.0 완료 선언은 유지하되, 증거 문서에 남은 운영·사용성·성능 미검증 항목을 3.0의 출발점으로 가져온다. 이 문서의 화면 관찰은 한 계정의 데스크톱과 390px 브라우저에서 확인한 표본이며 전체 사용자 행동이나 성능 측정 결과가 아니다.

## 제품 목적과 경계

Signal APT는 **내 조건에 맞는 집 후보를 빠르게 찾고, 왜 살펴볼 만한지와 무엇을 더 확인해야 하는지 한 흐름에서 판단하도록 돕는 서비스**다. 첫 집을 알아보는 구매자의 후보 발견·비교를 우선하고, 투자 관점의 시장 읽기와 경매는 목적과 위험이 다른 별도 판단 흐름으로 둔다. 지역 시그널은 시장 맥락이지 개별 매물의 매수 지시가 아니다. 예측·수익률·권리 안전을 검증 없이 확정적으로 말하지 않는다.

핵심 과업은 `내 조건 설정 → 후보 발견 → 두 후보 비교 → 근거와 반대 근거 확인 → 현장·서류에서 확인할 일 저장`이다. 홈·지도·시그널·리포트·찜 목록은 이 과업을 이어 주어야 하며 각각 독립적인 정보 전시장이 되어서는 안 된다.

## 승인된 제품·디자인 결정

1. 첫 화면은 알림 연결 배너나 긴 카드 목록보다 **내 후보의 변화 1~3개와 오늘 확인할 일**을 앞세운다. 연결 설정은 알림·설정 맥락으로 이동하되 실제 연결 상태와 이동 동선을 먼저 검증한다.
2. 매물 목록은 단건과 묶음 모두 `단지·지역 → 호가·전용면적 → 확인 상태` 순서로 읽힌다. 묶음은 건수·가격/면적 범위만 요약하고, 펼쳤을 때 같은 열 구조의 개별 후보를 보여 준다.
3. 매물 리포트 첫 화면은 `가격 상태 → 내 예산 → 선택 이유와 반대 근거 → 다음 확인` 순서다. 교통·학교·생활·비용·원천 한계는 주제별로 구별하되 작은 글씨의 반복 설명과 중첩 카드를 줄인다. 목록·지도·리포트 사이를 오갈 때 선택 매물과 탐색 위치를 보존한다.
4. 마지막 관측 호가는 날짜·원천과 함께 **마지막 확인 가격**으로 표시한다. 현재 거래 가능한 호가, 적정가, 내 예산 적합성으로 승격하지 않는다. 미확인 상태에는 자료 갱신 또는 검증 행동을 제시한다.
5. `지역 시그널`, `내 조건 적합`, `같은 면적·단지의 가격 근거`, `필요 자금`, `자료 충족도`를 분리한다. 하나의 추천 배지로 합성해 서로 다른 불확실성을 숨기지 않는다.
6. 일반매매·청약·경매는 성격이 다르므로 같은 추천 점수로 섞어 순위를 매기지 않는다. 찜 목록의 기본 비교는 동종 후보끼리 하고, 서로 다른 유형은 탭 또는 명시적 비교 모드로 나눈다.
7. 지역 가격 비교는 비교 대상·면적대·기간 선택과 핵심 숫자를 지도보다 앞에 둔다. 지도는 위치 이해를 돕는 두 번째 층이며, 표본 수·차이의 한계를 함께 보여 준다.
8. 모바일은 데스크톱 화면을 세로로 쌓지 않는다. 매물/지도 전환, 고정된 최소 조작 영역, 전체 화면 리포트와 명확한 닫기·복귀 위치를 설계한다. 잦은 필터·목록 조작에 장식적 애니메이션을 넣지 않는다.

메뉴의 목표 구조는 `오늘 / 매물 찾기 / 시장 읽기 / 내 후보`다. 지도는 후보 발견과 시장 읽기의 도구로 둔다. 이는 정보 구조의 목표안이며, 기존 딥링크와 사용자의 실제 과업을 확인하기 전 메뉴를 일괄 개명하거나 삭제하지 않는다.

| 단계 | 구현할 범위 | 완료 증거 |
| --- | --- | --- |
| 0. 신뢰 기준선 | 매물·지역·가격 원천별 수집 범위, 기준일, 마지막 성공·실패, `없음/오래됨/원천 실패/필터 제외`를 구분한다. 현재 화면과 데이터 계약을 대조하고 초보 구매자의 핵심 과업·모바일 동선을 기록한다. 기존 디자인 문서의 실제 코드와 충돌하는 규칙을 정리한다. | 표본·계정·시점이 명시된 화면/원천 감사표, 과업 실패 목록, 측정 가능한 성능 기준선. 미실행 항목은 미검증으로 남긴다. |

## 판정·추천·원천의 공통 계약

- 지역 시그널에는 관측일, 발행일, 적용된 규칙/설정 버전, 충족 조건, 미충족 조건, 반대 근거, 보류 사유를 남긴다. 동일한 광역 수치가 여러 구에 반복되더라도 구별 판정 차이를 만든 지역 고유 입력과 임계값을 함께 보여 준다.
- 개별 매물은 `호가/마지막 관측 호가/실거래/추정치`를 명확히 구분하고 출처·관측 시점·수집 시점을 기록한다. 원천별 허용 지연과 갱신 전략은 실측 후 정한다. 지난 가격으로 현재 거래 가능성이나 할인율을 단정하지 않는다.
- 가격 비교는 거래유형·전용면적대·기간·지역/단지 식별이 맞는 표본만 사용한다. 표본 수, 범위, 미통제 차이(층·연식·상태 등)를 보여 준다. 비교 불가인 경우 숫자를 채우기 위해 다른 타입을 섞지 않는다.
- 예산은 사용자가 확정한 입력과 가정값을 구분한다. 대출·세금·수리비가 없을 때는 가정 범위를 제시할 수 있으나 확정 매수력으로 표시하지 않는다.
- 청약은 일정·자격·공고문을 별도로 확인하고, 경매는 사건 문서·권리·점유·비용 미확인을 명시한다. 두 유형의 위험을 일반매매 추천 점수로 보정하지 않는다.

## 화면 품질 기준

- 시각 위계는 `판단에 필요한 값 → 그 값의 근거와 시점 → 다음 행동`이다. 카드 안의 카드, 축소된 설명문, 같은 사실의 반복 표시를 줄인다. 색만으로 시그널이나 위험을 전달하지 않고 텍스트와 상태를 함께 쓴다.
- Pretendard와 절제된 청색 기반은 유지하되 본문·상태 문구의 가독성을 우선한다. 실제 토큰·타이포·간격은 화면별 360~390px 및 데스크톱 검증 후 하나의 소스로 통합한다. 오래된 [디자인 시스템](../DESIGN.md)의 Nick·내비게이션·타이포 규칙은 현 제품과 충돌하므로 그대로 구현 기준으로 삼지 않는다.
- 버튼은 행동을 구체적으로 말하고, 로딩·빈 결과·권한 제한·원천 지연·오류는 서로 다른 상태로 표현한다. 필터 적용과 뒤로 가기는 선택과 스크롤 위치를 예측 가능하게 유지한다.
- 패널/리포트 전환에서만 짧고 중단 가능한 움직임을 사용한다. `prefers-reduced-motion`, 200% 확대, 키보드·초점 복귀, 터치 표적 크기를 회귀 조건으로 둔다. 180~220ms 같은 세부 시간은 프로토타입 테스트 후 결정한다.

## 검증·출시 게이트

기존 [출시 증거](SIGNAL-APT-2.0-RELEASE-EVIDENCE.md)의 미검증 항목을 통과로 간주하지 않는다. 초보 사용자 5명 중 4명이 3분 안에 지역 판정 이유·반대 근거를 찾고 추천 후보 두 개의 차이를 설명한다는 목표는 탐색적 과업 검사로 실행하고, 실패 화면·문구를 수정한 뒤 재확인한다. 이는 통계적 효과나 투자 성과 검증이 아니다.

성능은 원천 건수·계정·장치·네트워크·cold/warm 조건을 고정해 발견, 기본 리포트, 모바일 주요 내용 표시를 따로 측정한다. 기존 목표(warm 발견 p95 500ms, 기본 리포트 p95 800ms, 합의한 모바일 조건의 주요 내용 2초)는 측정 전에는 목표일 뿐이다. 운영 DB 지역 감사, 실제 백업 객체 복원, 배포 단계 전환·롤백 리허설은 별도의 담당자·권한·증거가 필요하다. 출시 뒤에도 잘못된 확신을 주는 가격·시그널·경매 표현은 정량 성능보다 우선해 수정한다.

## 아직 확정하지 않은 것

메뉴의 최종 명칭과 재배치, 개인화 추천 가중치, 원천별 TTL, 투자 성과 지표, 경매 상한의 보수 계수는 데이터·과업 검증 후 결정한다. 지도 공급사 교체, 자유형 AI 상담의 재도입, 신규 외부 원천의 대량 수집, 경매 권리 자동 확정, 전면 프런트엔드 재작성은 이 승인에 포함되지 않는다. 외부 데이터는 이용 조건과 제휴 범위를 재확인하며 인증 우회나 무단 수집을 추진하지 않는다. 구형 대화·개인 자료의 삭제나 이관은 별도 근거와 권한 없이 진행하지 않는다.
