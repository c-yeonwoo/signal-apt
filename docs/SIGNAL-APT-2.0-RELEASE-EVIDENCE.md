# Signal APT 2.0 출시 완료 판단과 증거 기록

이 문서는 구현·합성 테스트가 끝난 기능을 실제 사용자와 운영 환경에서 검증할 때 쓰는 체크리스트다. 2026-10-04 현재 CI 통과와 자동 배포만으로 2.0 완료를 선언하지 않는다. 미확인 항목은 `미검증`으로 남기고, 아래 증거가 쌓인 뒤 [전환·되돌리기 절차](SIGNAL-APT-2.0-ROLLOUT.md)에 따라 최종 출시 여부를 판단한다.

## 운영 데이터와 복구

백업 복원이나 데이터 이관은 이 문서만으로 승인되지 않는다. 현재 운영 자격증명과 백업 객체에 접근할 수 있는 담당자의 확인이 필요하며, 비밀값은 증거 문서에 붙이지 않는다.

지역 감사 API는 관리자에게만 제공하며 캐시를 금지한다. 결과에는 지역명·계정·매물 내용이 아니라 표면별 분류 건수와 KB 식별 증명 상태·관측일만 남긴다. `unique_legacy_name`은 현행 원천에서 유일하다는 뜻이지 과거 사용자의 선택 의도를 증명하거나 자동 이관을 허용하는 결과가 아니다.

2026-10-05 보조 점검: 배포된 공개 `/ready`는 위 상태를 반환했다. 워크스페이스 로컬 `data/cache/app.db`와 KB 캐시에서 읽기 전용 `signal region-audit` 및 `signal issued-outcomes`를 실행했으나, 로컬 KB의 identity manifest가 없어 `kb_identity_verified=false`였고 발행 판정 표본도 없었다. 이는 운영 DB 감사 결과가 아니며, 로컬 자료를 재생성하거나 검증 완료로 승격하지 않았다. 관리자 인증이 필요한 지역 상세 대조와 Railway 운영 DB 감사는 미검증으로 유지한다.

2026-10-05 운영 화면 부분 대조: 공개 `/ready`는 `ready=true`, `kb_source_fresh_for_signal=true`였고, 같은 로그인 세션의 지역 화면은 KB `2026-09-28`을 표시했다. 인천 개편 전 `동구`를 선택하면 주 배지는 `판단 보류`였으며, 새 구역으로 과거 값을 임의 분할하지 않고 현재 매수·매도 판정에 쓰지 않는다는 요약을 표시했다. 목록의 개편 전 `서구`와 `인천 중구`도 `판단 보류`로 보였고, 신설 `서해구`·`제물포구`는 별도 지역으로 나타났다. 이는 화면의 지역 안전 표시 한 시점만 확인한 것이며 운영 DB의 식별 manifest, 전체 지역 매핑, 발행 기록 감사까지 통과시킨 증거가 아니다. 상세 근거에는 `region_boundary_obsolete` 내부 코드가 노출돼 있어 수정 대상으로 기록했다.

PR #402 머지 `0574184`의 Railway 배포 `6846854140` 성공 후 같은 운영 계정의 새 UI 버전에서 인천 `동구`를 다시 열었다. 카드에는 `판단 보류 사유 2건`이 보이고, 펼친 근거에는 최근 4주 가격 부족과 행정구역 개편 전 자료를 현재 판정에 사용할 수 없다는 설명이 나타났다. `region_boundary_obsolete` 문자열은 보이지 않았고, 접힌 과거 규칙 등급은 펼쳤을 때 `관망 · 검증되지 않아 현재 판정으로 쓰지 않습니다`로 표시됐다. 한 지역·한 계정의 화면 확인으로, 전체 지역 감사·스마트폰·보조기기 검증을 대신하지 않는다.

PR #404 머지 `3b7982a`의 Railway 배포 `6846989813` 성공 후 같은 운영 계정에서 인천 `동구`를 다시 확인했다. 주 배지는 `판단 보류`이고 요약 카드의 첫 칸은 `판단 보류 이유`로 최근 주간 가격 4주 부족과 행정구역 개편 전 자료를 현행 매수·매도 판정에 쓸 수 없다는 설명을 바로 보여 줬다. 충족된 전세수급 압력은 요약 카드에 나오지 않고, 펼친 상세의 `기본 규칙의 충족 조건 · 현재 판정 아님` 아래에만 있었다. 한 지역의 실제 표시 순서를 확인했을 뿐, 초보자 이해도나 모든 보류 조합을 검증한 것은 아니다.

## 신호와 보고서의 판단 품질

발행된 시그널의 입력 기준일·지역 ID·계산 설정 해시·안전 판정·반대 근거가 지역 화면과 저장 리포트에서 일치해야 한다. 관측 지연, 원천 수정, 계산 방식 변경은 서로 다른 변화로 보여야 하며, 지역 자료가 보류된 동안 과거 원시 `BUY`를 현재 추천으로 표시하면 실패다.

복귀 브리핑의 구형 `signal_changes` 경로도 과거 기록으로만 남기고 현재 안전 판정과 일치할 때만 행동 문구를 보여 준다. 합성 `HELD`·판정 장애·유효 판정 회귀는 추가했으나, 운영의 과거 알림 로그와 저장본 전체가 같은 의미를 유지하는지는 계속 대조해야 한다.

기존 백테스트는 과거 원천의 당시 사용 가능 시각을 재현하지 못한 연구용 재구성이며, 일부 지역은 광역 수급 지표를 상속한다. 매수 등급의 미래 수익 확률이나 개인 매물의 투자 적중률로 해석하지 않는다. 예측 주장으로 승격하려면 실제 발행 기록만 따로 모아 동일 기간 시장 기준선, 지역 중복·상속, 미성숙 12주 결과를 구분해 평가해야 한다. 이 평가가 끝나기 전에는 판정 임계값을 성적표에 맞춰 임의 조정하지 않는다.

화면의 가입 문구·가이드·비교 모달도 과거 재구성임을 먼저 밝히고, `시장 대비 차이`를 인과적 기여로 부르지 않도록 수정했다. 이는 오해를 줄이는 변경이지 발행 시점 예측력을 입증하는 자료가 아니다.

운영 DB와 같은 KB 캐시가 있는 격리된 실행 환경에서 `signal issued-outcomes`를 실행하면 실제 `signal_assessments` 발행 기록을 읽기 전용으로 집계한다. 최초 발행 지역·관측주, `ready` 판정, 현재 KB 코드로 확인되는 지역만 대상으로 삼고 미성숙 12주·결측주·후속 수정본을 따로 센다. 같은 관측주·종료일의 전국 KB 방향과 비교하되 계산 설정별 결과를 합치지 않는다. 개인정보·지역명은 출력하지 않는다. 실제 운영 실행 결과와 각 방법별 표본·광역 지표 상속 수는 아직 확보하지 못했다. 현재 KB 시계열로 사후 가격을 계산하므로 당시 가격 원본의 수정 여부도 별도 한계다.

선택형 AI 설명은 실제 계정에서 요청 버튼을 누른 경우에만 호출되고, 사용량·비용·실패·근거 검증 결과를 확인한다. 기본 리포트 열람만으로 모델 비용이 생기면 실패다. 실제 문장에 근거 밖 숫자, 자격·권리 확정 또는 가격 전망 단정이 없는지 사람도 점검한다. 모델 사용량이 낮거나 높다는 사실만으로 설명의 충분성을 판단하지 않는다.

2026-10-04 운영 표본: 로그인된 계정에서 노원구 `쉽게 설명`을 한 번 요청했을 때 `deterministic_fallback`이 표시됐다. UI에서 관측한 것은 안전한 기본 설명이지 모델의 실제 실패 원인이나 호출 비용이 아니다. 이 표본을 모델 설명 품질 통과로 세지 않는다. 기본 설명은 지역·매물별 근거 연결과 반대 근거 우선 문구를 보강했고, AI 설명이 검증되지 않았음을 화면에서 밝히도록 했다.

추가 운영 관찰: 보강 배포 후 같은 지역의 새 설명 작업에서도 기본 설명이 표시됐고, 근거 연결·권역 공통 한계·반대 근거가 실제 화면에 나타났다. 원인은 기존 작업 기록에 남지 않아 알 수 없다. 이후 작업은 관리자 `/api/operations`의 7일 상태·실패 분류 집계와 LLM 사용량을 함께 대조한다. 집계만으로 모델 응답의 문장 품질이나 공급사 청구액을 증명하지 않는다.

## 발견과 화면의 실제 과업

초보 사용자 5명에게 같은 과업을 안내 없이 수행하게 한다. 개인 재산·소득·실주소는 테스트 계정에 입력하지 않는다. 360~390px 모바일과 데스크톱을 모두 포함하되, 기기·화면 폭·시작 화면을 참가자별로 기록한다.

> “한 지역을 골라 이번 주 판정의 이유와 조심할 근거를 찾으세요. 이어서 내 조건에 맞는 매물 후보 두 개를 열고, 어느 조건이 다르고 무엇을 추가 확인해야 하는지 설명해 주세요.”

시작부터 3분 이내에 지역 판정 이유와 반대 근거를 각각 정확히 찾고, 두 후보의 차이와 최소 한 가지 미확인 조건을 설명하면 한 명의 성공으로 센다. 5명 중 4명 이상 성공이 초기 통과 기준이다. 힌트·도움말을 받은 경우, 하나라도 원시 과거 등급을 현재 매수 판정으로 오해한 경우, 또는 호가를 실거래·구매 가능 확정으로 설명한 경우는 별도 실패 사유로 기록한다. 작은 표본의 탐색적 사용성 검사이며 투자 성과를 입증하지 않는다.

기록은 참가자 코드, 기기·화면 폭, 완료 시간, 성공 여부, 막힌 화면과 오해한 문구만 남긴다. 화면 녹화·정확한 주소·프로필 금액·자유 질문 원문은 수집하지 않는다. 실패 화면은 재현 후 수정하고 동일한 과업으로 다시 확인한다. Nick 채팅 진입점은 제품 결정에 따라 제거했다. 과업 검사는 리포트와 비교 화면만으로 질문을 해결할 수 있는지 평가한다.

2026-10-04 부분 증거: 합성 Chromium 360·390·1280px와 180px CSS 리플로우에서 조건 입력·후보·매물 리포트를 확인했다. 운영 개인 계정의 매물 1,881건 화면에서도 180px 뷰포트의 지도와 문서 가로 넘침이 없음을 재확인했다(지도/가용 폭 141/141px, 문서/뷰포트 165/180px). 실제 브라우저 200% 확대, 보조기기 및 위 5명 과업 결과는 여전히 미검증이다.

오래 열린 탭은 데이터 기준일과 별도로 HTML·리포트 UI 코드의 버전을 확인한다. 새 배포와 다르면 현재 입력을 자동으로 버리지 않고, 이전 방식의 시그널 설명일 수 있음을 고정 안내와 수동 갱신 버튼으로 알린다. 버전 공개 API에는 지역·개인 데이터가 없으며, 합성 API·UI 회귀로 ETag·불일치 안내·자동 새로고침 부재를 확인한다. 실제 배포를 가로지른 열린 탭 확인은 별도 운영 검증으로 남긴다.

## 지연과 단계 전환

인증된 개인 계정에서 일반매물 접근권과 수집 건수를 기록한 뒤, 조건별 발견·기본 매물 리포트를 각 30회 이상 측정한다. 저장소의 `scripts/benchmark_release.py`는 현재 로그인 쿠키와 매물 키를 환경에서 읽어 발견 POST와 cache-only 리포트를 순차 호출한다. 예: `SIGNAL_APT_SESSION_COOKIE`, `SIGNAL_APT_BENCH_LISTING_KEY`를 비밀값이 노출되지 않는 프로세스 환경으로 주입하고 필요하면 `SIGNAL_APT_BASE_URL`, `SIGNAL_APT_BENCH_SPEC_FILE`을 지정한 다음 `python scripts/benchmark_release.py --runs 30 --warmups 3`을 실행한다. 출력은 응답 내용·매물 키·쿠키·지역명을 제외한 요약이다. 캐시를 지우거나 원천을 새로 수집하지 않으며, 같은 HTTPS 호스트로의 리다이렉트도 따르지 않는다.

이 도구는 최초 요청과 반복 warm 측정만 하며 cold cache를 만들거나 검증하지 않는다. 장치·네트워크·요청 조건을 고정하고 측정 결과와 발견의 원천 건수를 별도 기록해야 한다. 최초 외부 보강과 선택형 AI 설명도 기본 리포트와 분리해 측정한다. [설계](SIGNAL-APT-2.0-DESIGN.md)의 초기 목표는 warm 발견 p95 500ms 이하, 기본 리포트 p95 800ms 이하, 합의한 모바일 조건에서 주요 내용 2초 이내다. 실제 계정 측정은 아직 실행하지 않았으므로 통과로 표시하지 않는다.

[전환·되돌리기 절차](SIGNAL-APT-2.0-ROLLOUT.md)의 각 스위치는 사전 합의한 점검 시간에 하나씩 끄고 켠다. 새 요청 차단, 화면의 대체 경로, 이전 저장본·발행 기록 보존, 원상 복구를 확인하고 운영 로그와 시간을 남긴다. 실제 전환을 하지 않았다면 코드 테스트 통과만으로 롤백 게이트를 통과시키지 않는다. 채팅 진입점을 다시 켜는 것은 롤백 절차에 포함하지 않는다.

## 완료 선언 조건

위 운영 복구, 지역 식별, 판정 품질, 실제 사용자 과업, 지연·비용, 단계 전환의 증거가 모두 확인되고 중대한 오판·권한 누출·복구 실패가 없을 때만 2.0을 완료로 표시한다. 이 문서는 증거 수집 방법이지 완료 기록이 아니다. 2.0 완료 후 경매 핸드오프를 별도 개선 로드맵으로 검토한다.
