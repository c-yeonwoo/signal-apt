# 경매 입찰 시뮬레이터 v1

옥션홈즈 `입찰가 산정표 vol19`의 목적별 비용 구조를 참고했지만 수식·세율·대출비율을 복사하지 않았다. 서비스에서 쓰는 계산 코어는 `src/realty_signal/auction_bid_engine.py`다. 기존 `auction.recommend()`의 감정가 1% 간격 단순 상한은 내부 호환 코드로 남겨 두었으나 목록·계산 API·낙찰 후 플랜의 자동 입찰가로 사용하지 않는다.

## 입력과 판단 상태

- 금액 단위는 만원이며 결과는 1만원 단위로 표시한다. 내부 비교는 반올림 전 수치로 한다.
- `needs_review`: 최저매각가, 권리·점유·인수 보증금, 보수적 시세, 취득세율, 사건별 입찰보증금, 명도비, 현금 한도 또는 목적별 목표가 빠진 상태. 상한과 총현금 모두 빈다.
- `assumption_only`: 사용자 입력으로 비용과 상한을 계산했으나 법원 서류·세금·대출·시장 표본 중 확인되지 않은 것이 있다. 화면에는 `가정상 상한 · 입찰 결정값 아님`으로 표시한다.
- `conditional_ceiling`: 법원 서류·세금·명도/관리/수리 비용·대출을 사용자가 확인했고, 국토부 수집 결과로 동일 단지·전용면적 ±0.1㎡·최근 6개월 실거래 3건 이상이 7일 안에 갱신됐으며 예비비를 넣은 경우. **사용자 확인 기준의 검토용 상한**이지 권리 안전성·은행 승인·적정 입찰가의 인증이 아니다.
- `no_bid`: 이번 회차 최저가부터 보수적 시세까지 목표와 현금 한도를 함께 만족하는 금액이 없다.

국토부 표본은 `auction.update_market()`의 관리자 갱신 경로에서만 캐시에 들어간다. 상세의 관리자 버튼은 현재 물건 하나만 갱신한다. 직접 전달한 API 거래 목록은 공식 수집 표본으로 승격하지 않는다. 수집 실패·표본 부족은 시세 0원으로 처리하지 않으며, 과거 캐시의 갱신일은 새로 쓰지 않는다. 단일 최근 실거래가는 화면 참고값일 뿐 공식 표본 3건을 대체하지 않는다. 일반 매물 호가, 감정가, 다른 면적 거래를 적정 시세에 섞지 않는다.

## 계산

`경매총비용(b) = b + b×사용자확인_최대취득세율 + 법무비 + 확인된인수액 + 명도비 + 미납관리비 + 수리비 + 예비비 + 실제반영대출×금리×보유개월/12`.

`실제반영대출 = min(입력한 확인 대출액, b−법원공고 입찰보증금)`이다. 대출액을 입력하지 않으면 0원이다. 승인 여부를 알 수 없는 기존 LTV 70%·80% 기본값은 새 엔진에 쓰지 않는다.

최대 필요 현금은 입찰보증금, 잔금·취득, 명도·수리, 보유 순으로 누적된 현금 유출의 최댓값이다. 임대보증금은 임대 개시 이후에만 유입으로 표시하고 반환 의무도 표시한다. 잔금 전에 들어오는 돈으로 간주하지 않는다.

- 실거주: `보수적 시세 기준 일반매수 총비용 − 경매총비용 ≥ 사용자 목표 절약액`.
- 단기매도: `보수적 매도가 − 매도 중개비 − 사용자 확인 최대 매도세금 − 경매총비용 ≥ 사용자 목표 순이익`.
- 임대: `연 임대료×(1−공실률) − 연 운영비 − 대출 연이자 − 연 원금상환 ≥ 0`이고, 이 금액을 `경매총비용−대출−임대보증금`으로 나눈 현금 수익률이 목표 이상이어야 한다. 분모가 0 이하면 수익률을 확정하지 않는다.

세 목적 모두 `최대 필요 현금 ≤ 사용 가능 현금`을 만족해야 한다. 상한은 최저가부터 보수적 시세까지의 1만원 단위 최고 통과 가격을 단조 구간 이분 탐색으로 찾는다. 임대의 순투입 현금이 0 이하인 구간은 먼저 제외한다. 과거 낙찰가율 평균과 심리적 가격선은 상한을 높이는 근거로 사용하지 않는다.

## 화면·기존 API

`POST /api/auction/scenario/{listing_id}`가 저장 없는 계산을 수행한다. 경매 목록은 목적·현금·세금이 없으므로 상한을 제시하지 않고 최저매각가와 확인할 근거만 보여 준다. 상세에서 목적별 입력, 입찰가 슬라이더, 비용·최대 현금·목표 결과와 단계별 현금 유출을 한곳에서 본다. 기존 `/api/auction/calc/{listing_id}`는 호환 필드를 돌려주지만 추천 입찰가는 비워 둔다. 기존 낙찰 후 플랜도 자동 추천가와 일률적인 10% 입찰보증금을 사용하지 않으며, 명시적 입찰가/낙찰가와 사건별 보증금이 있어야 열린다. 매각허가결정일·대금지급기한은 입력된 법원 날짜만 표시하고 없으면 비운다. Telegram 브리핑도 고정 D+일이 아닌 입력된 사건별 날짜에만 알린다.

통합 매물의 경매 상세와 경매 전용 목록 모두 `내 입찰 상한 계산`으로 이어진다. 자동 수집 행크 카드는 이미 저장된 목록 캐시의 최저매각가·사건번호·기일만 사용하며, 상세 페이지를 새로 긁거나 건물면적을 전용면적으로 바꾸지 않는다. `GET /api/auction/calc/hank:{id}`는 저장 없는 초기값만 제공한다. `POST /api/auction/scenario/hank:{id}`에서는 사용자가 확인한 전용면적과 인수금액 가정을 입력할 수 있으나, 권리·점유 직접 검토 체크와 금액 입력이 없으면 계산을 보류한다. 입력해도 공식 검증 자료로 승격되지 않으며 결과는 최대 `assumption_only`이고 `review_ceiling`은 비어 있다. 실거래 표본·세율·대출과 법원 서류의 실제 정합성은 별도 확인 대상이다.

공개 목록·계산 응답은 권리자·임차인 이름 및 자유 메모 원문을 제외하고 조사완료 여부만 전달한다. 저장된 권리·임차인 원문 조회는 관리자에게만 허용한다. 공개 사용자는 법원 원본 서류를 직접 확인해야 한다.

## 남은 검증과 제한

- 세금은 자동 정책 엔진이 아니라 사용자가 확인한 **입찰 범위 최대 세율/세금**을 쓴다. 주택 수·지역·취득 주체가 달라지면 다시 확인해야 한다.
- 대출은 확인받은 금액만 반영하지만 실행일, 상환 방식, 중도상환수수료, 법적 대출 한도는 자동 검증하지 않는다. 입력하지 않은 대출은 0원이다.
- 권리 분석은 기존 수동 입력·확인 체크를 재사용한다. 원본 서류의 정합성, 점유·인수액, 배당 결과를 자동 인증하지 않는다.
- 국토부 실거래 표본은 같은 단지·전용면적까지만 맞춘다. 층, 향, 상태, 거래 취소 여부가 충분히 검증되지 않은 경우 실제 매수가치를 보장하지 않는다.
- 운영에서 실제 법원 서류, 세무·금융기관 견적, 낙찰 사례와 결과를 대조하는 검증은 아직 하지 않았다. 이 문서와 테스트 통과를 운영 검증으로 기록하지 않는다.
